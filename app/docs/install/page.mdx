# Install

<Lede>
Docker, and nothing else. One image holds the control plane, the interface
compiled into the binary, and what a session needs to run. Migrations apply at
start-up, so there is no migrate command to remember.
</Lede>

## Fetch the compose file

```sh
curl -O https://raw.githubusercontent.com/firetower-cloud/firetower/main/deploy/firetower.yml
curl -O https://raw.githubusercontent.com/firetower-cloud/firetower/main/deploy/Caddyfile
curl -o .env https://raw.githubusercontent.com/firetower-cloud/firetower/main/deploy/.env.example
```

Fill in `POSTGRES_PASSWORD` in `.env`. Set `FIRETOWER_ROOT_KEY` too if you would
rather the key that opens your credentials never touched the disk — see
[Secrets](/docs/secrets).

## Start it

```sh
docker compose -f firetower.yml up -d
```

## Read the log

The first start makes an administrator and prints its password once. Set
`ADMIN_INITIAL_PASSWORD` in `.env` beforehand if you would rather choose it.

```sh
docker compose -f firetower.yml logs firetower
```

<Output>{`  There was no administrator, so one was made:

    username  admin
    password  velvet-timber-harbor-332`}</Output>

Sign in with it and Firetower asks you to replace it — the one it printed was in
a log, and the one you might have set is in a file. Afterwards those variables
are ignored, so editing an unrelated line of your `.env` cannot reset it.

There is deliberately no moment where a fresh Firetower on a public address sits
unclaimed, waiting for whoever reaches it first to become its owner.

## What you have now

Sessions run in that container, the same way they run on a laptop: the control
plane starts a worker as a child process, and `localhost` is a real host in the
fleet rather than a special case. To run them somewhere else, [add a
machine](/docs/hosts) and drain `localhost`.

Only Caddy publishes a port. The control plane holds every credential Firetower
has and is reachable from nothing but the proxy in front of it, which matters
more than the certificate does.

<Callout>
Forgotten the password? There is no reset email, and one supported way back in:
`docker compose -f firetower.yml exec firetower firetower passwd admin`.
</Callout>
