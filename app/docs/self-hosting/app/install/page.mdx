# Which config is good for you?

<Lede>
The control plane is the part you open in a browser, and it runs on one
machine. There are two ways to install it. `firetower install` asks which one
you want as its first question — everything after that follows from the answer.
</Lede>

## From localhost

Firetower publishes on `127.0.0.1` and nothing else. Two ways to use that.

**On your own computer.** Open it in a browser. Nothing else to set up.

<Diagram caption="Nothing is published to the network.">{`
  +-- YOUR MAC -------------------------+
  |                                     |
  |   browser  -->  localhost:8080      |
  |                      |              |
  |                 firetower           |
  |                 postgres            |
  |                                     |
  +-------------------------------------+
`}</Diagram>

**On a remote server.** Forward the port over SSH, then open it on your laptop.

<Diagram caption="firetower tunnel you@server — open for as long as you are using it.">{`
  +-- YOUR MAC --------------+           +-- YOUR SERVER --------------+
  |                          |           |                             |
  |   browser                |    ssh    |   firetower                 |
  |      |                   |   tunnel  |   postgres                  |
  |      v                   |           |      ^                      |
  |   localhost:8080 ---------------------------+                      |
  |                          |           |   127.0.0.1:8080            |
  +--------------------------+           +-----------------------------+
`}</Diagram>

| | |
| --- | --- |
| **Pros** | Nothing to configure — no domain, no certificate, no VPN. The fastest way to see Firetower running. |
| **Cons** | No custom domain. From a server, a tunnel has to be open. No access from a phone, and none for your team. |

**[Install on localhost →](/docs/self-hosting/app/install/localhost)**

## With a custom domain

Firetower gets a domain name and a certificate, and everyone on your mesh
network reaches it from any device.

<Diagram caption="The domain is in public DNS. The address it resolves to is private, so only devices on the tailnet can connect.">{`
   your mac        your phone        a teammate
       |               |                 |
       +------- TAILSCALE TAILNET -------+
                       |
                       |  https://firetower.example.com
                       |  A record  -->  100.92.14.7
                       v
       +-- YOUR SERVER ----------------------+
       |                                     |
       |   caddy  -->  firetower             |
       |   443         on 127.0.0.1:8080     |
       |                                     |
       +-------------------------------------+
`}</Diagram>

<Callout>
A custom domain does not mean public access. The A records point at a private
address, so Tailscale — or another mesh VPN — is required on the server and on
each device. The certificate is obtained over DNS-01, which needs no inbound
connection.
</Callout>

| | |
| --- | --- |
| **Pros** | Reachable from every device on the tailnet, with no tunnel to open. Real HTTPS. Working preview URLs. Usable by your team. |
| **Cons** | More setup: Tailscale, two DNS A records, and an API token for your DNS provider. The first install waits while the certificate is issued. |

**[Install with a custom domain →](/docs/self-hosting/app/install/domain)**

## You can switch later

Neither choice is permanent and neither needs a reinstall. `firetower domain`
adds a domain to a running deployment; `firetower domain --none` removes it and
puts the deployment back on loopback.
