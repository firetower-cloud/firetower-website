Recommandation : suivre le travail dans une PR en brouillon

Pour les projets GitHub, demandez au responsable d’utiliser la CLI gh pour créer une pull request en brouillon et la tenir à jour pendant le travail de l’équipe. Les agents peuvent y consigner l’avancement, les vérifications et les conclusions de la revue. Firetower permet aussi de consulter les modifications et de les publier depuis l’application.

Exemple de demande
Utilise gh pour ouvrir une PR en brouillon pour cette tâche.
Tiens-la à jour avec les modifications, vérifications et conclusions de chaque agent.
Laisse-la en brouillon jusqu’à ce que je l’aie relue.

Ouvrez l’espace de travail, puis sélectionnez Diff dans le panneau de droite pour examiner les fichiers modifiés.

Relire le travail

  1. Lisez la synthèse de l’agent. Comparez le résultat à la demande initiale.
  2. Examinez les fichiers modifiés. Repérez les modifications hors sujet, les données sensibles et les changements de comportement.
  3. Vérifiez les contrôles effectués. Consultez les résultats des tests et relancez les vérifications nécessaires dans l’espace de travail.
  4. Demandez des corrections. Formulez des demandes précises et vérifiez les modifications mises à jour.

Publier sur votre plateforme Git

Utilisez la fonction de publication de l’espace de travail pour créer ou mettre à jour une pull request ou une merge request. Votre compte Git doit pouvoir pousser des modifications et créer cette demande. Terminez la revue et la fusion selon le processus habituel de votre équipe.

En cas d’échec de la publication

  • Vérifiez si votre jeton Git a expiré ou perdu l’accès au dépôt.
  • Vérifiez les droits d’écriture et les autorisations du jeton.
  • Résolvez les conflits de branches avant de réessayer.
  • Vérifiez que vous agissez dans votre propre conversation avec l’agent.

Vous travaillez sans dépôt ? Téléchargez le résultat au lieu d’utiliser la publication Git.
