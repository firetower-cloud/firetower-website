  • Un serveur Linux que vous administrez, avec un accès SSH et les droits root ou sudo pour l’installation.
  • Docker avec le plugin Compose. Node.js 20 ou version ultérieure pour l’outil d’installation en ligne de commande. Le script d’installation peut installer ces prérequis.
  • Un domaine, l’accès à ses enregistrements DNS et un jeton API du fournisseur DNS pour obtenir les certificats.
  • Un accès réseau permettant de télécharger les fichiers de déploiement, les images de conteneurs et les composants nécessaires aux certificats.

Machines d’exécution

Firetower exécute les agents directement, sans conteneur par agent. Les besoins en processeur et en mémoire dépendent des agents, des tâches et du nombre d’exécutions simultanées.

Un Mac mini avec 16 Go de mémoire constitue un bon point de départ. Un VPS de 8 Go ou moins peut suffire pour des tâches légères. Les compilations, les tests et les gros dépôts peuvent demander davantage de ressources.

Séparez les workers du plan de contrôle

N’exécutez pas vos agents sur le même VPS que le plan de contrôle. Utilisez une machine distincte pour leur travail.

Les workers fonctionnent sur macOS et Linux, avec les architectures arm64 et x86_64. Sous Windows, installez le worker dans WSL2.

  • Un accès SSH depuis le plan de contrôle, avec un compte dédié au travail des agents.
  • Git, tmux, un shell POSIX, curl et tar.
  • Les agents de développement et les outils nécessaires à vos projets.
  • Un accès à vos plateformes Git, aux fournisseurs des agents et aux dépendances des projets.
Des prérequis distincts

Le worker Firetower ne nécessite ni Node.js ni Docker pour fonctionner. En revanche, un agent ou votre projet peut en avoir besoin.

Utilisateurs et appareils

Fournissez une URL HTTPS accessible et un compte Firetower à chaque personne. Installez le VPN de l’entreprise sur les appareils qui ont besoin d’un accès privé.
